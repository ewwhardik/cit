## 2. What the LLM is NOT allowed to decide

- Whether a timetable, exam schedule, booking or change is valid. That is
  always `engine/app/checker.py` (deterministic code, tested against the
  official `validator.py`).
- Booking priority / category. The category is capped by the authenticated
  user's role in code; an LLM claim ("this is an institute event") is ignored.
- Approvals. Only a human approver (never the requester) applies a change.
- Final room and time. LLM output is only a *draft* the user edits; the
  engine allocates and checks.
- The LLM never writes to the database. Every LLM output is parsed with a
  Zod schema and then validated by the engine before anything changes.
- If the LLM API fails or has no key, the manual booking form and a
  deterministic parser still work.

Reasons attached to booking decisions ("No venue seats 1,200 people…") are
generated by code from structured facts (`engine/app/bookings.py`).
